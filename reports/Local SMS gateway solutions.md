# Local SIMs beat cloud SMS APIs
Shops and desktop apps that refuse vendor SMS clouds already converge on **physical-SIM radios** — spare Android phones with LAN HTTP gateways, USB LTE sticks driven by Gammu/Kannel/smstools, or multi-port appliances with HTTP/SMPP — because airtime rides the operator plan they already pay for and the control plane can stay on the LAN. The densest true-local Android options are Capcom’s **SMSGate Local mode**, LibreSMS, Traccar’s phone-direct API, PlainApp, and KDE Connect; many commercial “phone SIM” products (SimGate, Telerivet, SMS Forwarder.app, textbee hosted) still relay control through vendor clouds and FCM even when the radio is a handset ([sms-gate.app](https://sms-gate.app/); [LibreSMS](https://fictus.github.io/LibreSMS/); [Traccar HTTP SMS API](https://www.traccar.org/http-sms-api/); [textbee self-hosting](https://textbee.dev/docs/self-hosting)). Reliability fails more often from OEM battery killers, Wi-Fi sleep, HiLink-vs-modem mode, and carrier spam filters than from HTTP design ([SMSGate FAQ](https://docs.sms-gate.app/faq/general/); [textbee battery guide](https://textbee.dev/blog/android-sms-gateway-not-sending-battery-optimization); [Big Iron modem guide](https://www.bigiron.cc/guides/sms-self-hosted-gammu-vs-smstools3-for-otp-and-alerting)). Wadhu can win by treating SMS like a local print spooler: a brand-neutral **outbox + capability protocol** in crates, and an independent **SMS-Gateway** Makepad app that owns pairing, queues, Android/USB backends, and policy — so Kumkaj and third parties enqueue once and never speak AT or OEM battery lore.

## Android LAN gateways own mindshare; “uses my SIM” often still means cloud
Among FOSS projects, Capcom’s **SMS Gateway for Android** (SMSGate, ~6k GitHub stars) is the clearest developer default: Local Server mode binds `http://<device_ip>:8080/message` with Basic auth, no account, Swagger docs, multipart send, webhooks for received/sent/delivered/failed, multi-SIM rotation, rate limits, schedules, and delivery-report toggles — while Cloud and Private modes add FCM-woken internet reachability ([GitHub README](https://github.com/capcom6/android-sms-gateway/); [Local Server](https://docs.sms-gate.app/getting-started/local-server/); [Sending Messages](https://docs.sms-gate.app/features/sending-messages/)). LibreSMS and Traccar SMS Gateway follow the same pattern with on-device HTTP (ports **8686** and phone-local URLs respectively); Traccar also offers an optional `traccar.org` relay that reintroduces a third-party hop ([LibreSMS](https://fictus.github.io/LibreSMS/); [Traccar HTTP SMS API](https://www.traccar.org/http-sms-api/)). Desktop-companion products such as **KDE Connect**, PlainApp, and EasyJoin emphasize human SMS UI over bulk queues, with LAN TLS or browser HTTPS rather than OpenAPI-first DX ([kdeconnect-kde](https://github.com/KDE/kdeconnect-kde); [plainapp.app](https://plainapp.app/); [EasyJoin features](https://easyjoin.net/features.html)). SmsForwarder’s ~29k stars show consumer demand for OTP-forward-to-chat, not for a stable multi-tenant REST outbox ([SmsForwarder](https://github.com/pppscn/SmsForwarder)).

The sharp product cut is control-plane locality. SMSGate Local, LibreSMS, Traccar phone URL, PlainApp, KDE Connect LAN, self-hosted MQTT (ibnux), and Tasker local HTTP can keep both radio and API on the shop network; textbee self-host still depends on **Firebase Cloud Messaging** to wake the phone, and SimGate/Telerivet/SMS Forwarder.app expose vendor HTTPS APIs even though SMS leaves a physical SIM ([textbee self-hosting](https://textbee.dev/docs/self-hosting); [simgate.app](https://www.simgate.app/); [Telerivet app](https://www.telerivet.com/product/app); [smsforwarder.app](https://smsforwarder.app/)). Integrators praise cost and local numbers, then abandon phone gateways when Doze, Xiaomi/Samsung killers, or Wi-Fi sleep stall the queue silently — the tell is a missing foreground notification or “pending forever,” not a clean API error ([r/androiddev 2025](https://www.reddit.com/r/androiddev/comments/1mpzx7o/whats_the_best_android_sms_gateway_app_for_a_client_project_in_2025/); [SMSGate Local Server FAQ](https://docs.sms-gate.app/faq/local-server/); [textbee battery guide](https://textbee.dev/blog/android-sms-gateway-not-sending-battery-optimization)). Android platform constraints compound that: KitKat+ SMS architecture, Play’s default-SMS-handler rules for SMS permission groups, AOSP’s roughly **30 SMS / 60s** gate for non-default apps, dual-SIM `SubscriptionManager` ambiguity, sideload Play Protect blocks, and the absence of public RCS APIs ([Play SMS/Call Log policy](https://support.google.com/googleplay/android-developer/answer/10208820); [AOSP SmsUsageMonitor](https://android.googlesource.com/platform/frameworks/opt/telephony/+/refs/heads/main/src/java/com/android/internal/telephony/SmsUsageMonitor.java); [SMSGate FAQ](https://docs.sms-gate.app/faq/general/)). Becoming the default SMS app unlocks inbound STOP handling and removes the OS rate gate, but forces a real messaging UI and a first-run role prompt — SMSGate deliberately refuses default status for transparency; LibreSMS requires it for inbound ([SMSGate FAQ](https://docs.sms-gate.app/faq/general/); [LibreSMS](https://fictus.github.io/LibreSMS/); [Android default handlers](https://developer.android.com/guide/topics/permissions/default-handlers)).

## USB modems and appliances remain the 24/7 path, with AT ops tax
When the radio must survive power loss and overnight OTP/alerts, operators attach **AT-command modems** rather than daily-driver phones. Actively useful stacks in 2025–2026 are **Gammu SMSD** (upstream releases through October 2026), **ModemManager/`mmcli`**, **Kannel** AT SMSC (upstream frozen at 1.4.5 but still Debian-packaged), **smstools3** (stable spool daemon, site last updated 2017), and **playSMS** as a web/management layer over those backends ([Gammu releases](https://github.com/gammu/gammu/releases); [mmcli man page](https://www.freedesktop.org/software/ModemManager/man/latest/mmcli.1.html); [Debian kannel](https://tracker.debian.org/pkg/kannel/news/); [smstools3](https://smstools3.kekekasvi.com/); [playsms](https://github.com/playsms/playsms)). Wammu and gnokii are legacy; FreeSWITCH `mod_sms` is SIP SIMPLE chat, not cellular; Jasmin’s open-source core wants SMPP upstream and needs a commercial plugin for serial modems ([Wammu](https://wammu.eu/wammu/); [FreeSWITCH mod_sms](https://github.com/signalwire/freeswitch-docs/blob/main/docs/FreeSWITCH-Explained/Modules/mod_sms_6587288.mdx); [jasmin#697](https://github.com/jookies/jasmin/issues/697)). Hardware classes map cleanly: consumer Huawei E3531/E3372 and industrial Quectel/SIM7600 sticks in **modem mode**, classic Wavecom/Sierra AT boxes, and Dinstar/OpenVox/SMSEagle multi-port appliances that already speak HTTP SMS and often SMPP ([Big Iron hardware](https://www.bigiron.cc/guides/sms-self-hosted-gammu-vs-smstools3-for-otp-and-alerting); [Dinstar UC2000-VG](https://www.dinstar.com/GSM-3G-LTE-voip-gateway/32-ports/); [SMSEagle 2026 ranking](https://www.smseagle.eu/2026/08/07/best-sms-gateway-solutions-in-2026-comparison-ranking-and-buying-guide/)).

Feature floors on these stacks include file or SQL outboxes, Unicode/concatenation, inbound hooks, and delivery-report requests; multi-SIM failover and USSD are strongest on appliances and ad-hoc on single sticks ([smstools3](https://smstools3.kekekasvi.com/); [Gammu SMSD tables](https://docs.gammu.org/smsd/tables.html); [Dinstar Multi-SIM](https://www.dinstar.com/GSM-3G-LTE-voip-gateway/multi-sim-gateway/)). Business apps almost never speak raw AT: they drop spool files, insert SQL outbox rows, or call Kannel/playSMS/appliance HTTP ([Big Iron](https://www.bigiron.cc/guides/sms-self-hosted-gammu-vs-smstools3-for-otp-and-alerting); [visibilityspots SMS server](https://visibilityspots.github.io/blog/sms-server.html)). The ops tax is familiar and brutal — HiLink firmware without serial ports, ModemManager claiming the tty, unstable `/dev/ttyUSB*` numbering, SIM PIN locks, CMS ERROR 21/28 network rejects misread as modem faults, USB brownouts, and ~**6–10 SMS/min** DIY channel throughput ([zaage.IT E3372](https://zaage.it/writing/flashing-huawei-e3372h-4g-lte-from-hilink-to-modem-mode/); [Diafaan CMS errors](https://www.diafaan.com/support-forum/using-diafaan-sms-server/8-port-usb-gsm-modem-pool-refuses-to-send-messages/); [Big Iron](https://www.bigiron.cc/guides/sms-self-hosted-gammu-vs-smstools3-for-otp-and-alerting)). Cheap Android (~$20 phone + prepaid) wins PoC CAPEX; dedicated modems and ~690–2100+ EUR appliances win continuous duty and buffering, while both still pay airtime and face the same consent and anti-spam walls ([jonno.nz Android gateway](https://jonno.nz/posts/built-an-sms-gateway-with-a-20-dollar-android-phone/); [SMSEagle build or buy](https://www.smseagle.eu/2026/11/06/sms-server-build-or-buy/)).

## Integrators need one outbox contract, not curl-to-phone-IP folklore
Across local and cloud DX, the durable integration shape is **REST accept → durable queue → status poll + webhook push**, with optional WebSocket for same-LAN UIs and MQTT only when a local broker already exists ([SMSGate webhooks](https://docs.sms-gate.app/features/webhooks/); [sms-server WebSocket](https://github.com/morgverd/sms-server/blob/b638b71e921254939b97f0be8342c7242dd1d0cb/docs/websocket.md); [Twilio message statuses](https://www.twilio.com/docs/messaging/guides/track-outbound-message-status)). Radio send is at-least-once: clients need Stripe-style **Idempotency-Key** on accept; gateways must not auto-retry after ambiguous submit (SMSGate’s stuck `Processed` lesson); webhooks retry with backoff and consumers must dedupe on `messageId`+event ([Stripe idempotent requests](https://docs.stripe.com/api/idempotent_requests); [SMSGate status tracking](https://docs.sms-gate.app/features/status-tracking/); [SMSGate webhooks](https://docs.sms-gate.app/features/webhooks/)). A public state machine that separates `queued`, `submitting`, `submitted`, `delivered`, `failed`, `expired`, `cancelled`, and optional `indeterminate` maps cleanly onto SMSGate, Twilio, MessageBird, and Gammu enums and prevents the fatal mistake of retrying after radio handoff ([SMSGate status tracking](https://docs.sms-gate.app/features/status-tracking/); [MessageBird SMS API](https://developers.messagebird.com/api/sms-messaging/); [Gammu SMSD tables](https://docs.gammu.org/smsd/tables.html); [textbee battery guide](https://textbee.dev/blog/android-sms-gateway-not-sending-battery-optimization)). Multi-client shops require **one process owning the radio and outbox**; Gammu explicitly forbids two programs driving the same phone, while SMSGate’s cloud JWT scopes show how to isolate clients with least privilege ([Gammu SMSD limitations](https://docs.gammu.org/smsd/smsd.html); [SMSGate API integration](https://docs.sms-gate.app/integration/api/)).

Pairing is where incumbents look dated. SMSGate Local still surfaces IP + Basic credentials and curl; better local UX elsewhere uses DNS-SD/mDNS plus short-lived QR pairing grants with TLS fingerprint pinning, never long-lived secrets in the QR ([SMSGate Local Server](https://docs.sms-gate.app/getting-started/local-server/); [RFC 6763](https://www.rfc-editor.org/rfc/rfc6763.html); [draft-ietf-dnssd-pairing-info-02](https://www.ietf.org/archive/id/draft-ietf-dnssd-pairing-info-02.txt); [Autobutler PR #1423](https://github.com/autobutler-org/autobutler/pull/1423)). Product-grade third-party adoption further wants OpenAPI, typed SDKs, `GET /capabilities` and health, dry-run that walks the state machine without touching radio, webhook HMAC, and append-only audit — SMSGate and sms-server already point there; dry-run and rich capability blobs remain under-served differentiation ([SMSGate API](https://docs.sms-gate.app/integration/api/); [sms-server](https://github.com/morgverd/sms-server); [SMSEagle API](https://www.smseagle.eu/api/)). Adjacent domains already solved the mental model: CUPS/IPP treat the spooler as system of record with backends underneath; Star CloudPRNT confirms pairing with a tangible welcome print; Stripe Terminal pairs while healthy then store-and-forwards offline ([Ubuntu Samba print server](https://ubuntu.com/server/docs/how-to/samba/print-server.md); [Star CloudPRNT](https://star-m.jp/products/s_print/sdk/StarCloudPRNT/manual/en/); [Stripe Terminal offline](https://docs.stripe.com/terminal/features/operate-offline/overview?reader-type=bluetooth)).

Compliance is a hard product boundary, not a docs footnote. CTIA treats automated business messaging as **Non-Consumer (A2P)** even under illustrative consumer velocity envelopes (~15–60/min, ~1,000/day); carriers filter and blocklist anyway ([CTIA Messaging Principles 2023](https://api.ctia.org/wp-content/uploads/2023/05/230523-CTIA-Messaging-Principles-and-Best-Practices-FINAL.pdf); [Twilio P2P vs A2P](https://help.twilio.com/articles/223133807-What-is-P2P-and-A2P-messaging-)). India’s TRAI TCCCPR (Feb 2025 amendment) treats commercial communication from **unregistered** senders as UCC and pushes registered headers/templates/DLT scrubbing — purpose, not SIM type, drives the rule — so a handset gateway is a poor promotional path and legally fragile for scaled commercial traffic without counsel ([TRAI Regulation PDF](https://www.trai.gov.in/sites/default/files/2025-02/Regulation_12022025.pdf)). EU ePrivacy and US TCPA/FCC revocation rules (STOP keywords, 10-business-day honor, no exclusive opt-out channel) apply to automated phone sends the same as cloud CPaaS ([EUR-Lex ePrivacy summary](https://eur-lex.europa.eu/EN/legal-content/summary/data-protection-in-the-electronic-communications-sector.html); [FCC DA-25-312](https://docs.fcc.gov/public/attachments/DA-25-312A1.pdf)). The gateway — not each client — must enforce message class, consent references, quiet hours, hard caps well below CTIA envelopes, templates, audit logs, and inbound STOP suppression ([CTIA 2023](https://api.ctia.org/wp-content/uploads/2023/05/230523-CTIA-Messaging-Principles-and-Best-Practices-FINAL.pdf); [FCC DA-25-312](https://docs.fcc.gov/public/attachments/DA-25-312A1.pdf)).

## Wadhu ships a spooler crate and an independent SMS-Gateway app
Wadhu’s independence rules already dictate the cut: reusable protocol and client live in **brand-neutral crates**; the operator-facing program is a standalone **app** that other Gotigin brands and third parties talk to over LAN/HTTP (or USB), never by importing sibling apps ([WADHU_VISION_AND_PRINCIPLES.md](../docs/WADHU_VISION_AND_PRINCIPLES.md)). The library surface should be one crate (or a carefully feature-gated family that still obeys “no sibling crate deps” via copy-then-diverge if split later): outbox item schema (`id`, `idempotency_key`, `to`, `body`, `priority`, `created_at`, `expires_at`, optional `backend_hint`), the status enum and safe-retry table, capability document, pairing token types, OpenAPI, and a Rust client — optional Makepad widgets behind a `widgets` feature of the same crate if shared UI primitives help ([CRATES.md](../docs/CRATES.md); [Stripe idempotency](https://docs.stripe.com/api/idempotent_requests); [SMSGate sending](https://docs.sms-gate.app/features/sending-messages/)). Apps such as Kumkaj enqueue intents and watch status; they never learn SMSGate vs Quectel quirks. Explicit non-goals for v1 match the gaps research: no hosted blast SaaS, no WhatsApp/RCS replacement, no mandatory Gotigin cloud control plane, no unsupported USB free-for-all ([SMSGate FAQ](https://docs.sms-gate.app/faq/general/); [textbee battery guide](https://textbee.dev/blog/android-sms-gateway-not-sending-battery-optimization); [ProCat modem post](https://procatsolutions.com/en/blog/sms-gateway-and-gsm-modems/)).

The **SMS-Gateway** app (created via `./scripts/new-app.sh`, own `env/`, `scripts/`, `docs/`, `tools/<app>-dev`) hosts the durable outbox on the shop desktop or LAN host, exposes versioned HTTPS (loopback default; LAN bind after pairing), drains through backend adapters, and owns shop UX. Backend v1 is an Android companion agent that registers capabilities (`sims[]`, `sms_per_minute`, `supports_dlr`, transport) and submits claimed jobs; backend v1.5 is a USB modem worker via ModemManager or a thin Gammu/AT adapter with an explicit supported-device allowlist; later backends can wrap Dinstar/SMSEagle-class HTTP without changing clients ([mmcli](https://www.freedesktop.org/software/ModemManager/man/latest/mmcli.1.html); [SMSEagle features](https://www.smseagle.eu/features/); [ProCat](https://procatsolutions.com/en/blog/sms-gateway-and-gsm-modems/)). Routing policy prefers dedicated modem over daily-driver phone, fails over on health loss, and **never** fans one idempotency key to two radios. Pairing UX copies the print/payment pattern: advertise `_wadhu-sms._tcp` with TXT `ver`/`fp`/`caps`, QR carries a single-use grant + TLS SPKI pin, test SMS to the owner’s number completes pairing, and the home screen shows three lights — Radio, Link, Queue — plus an OEM battery wizard and plain-language errors (“phone went to sleep,” “SIM out of credit,” “carrier blocked”) ([RFC 6763](https://www.rfc-editor.org/rfc/rfc6763.html); [Star connecting a device](https://docs.starprinter.online/articles/connecting_a_device.html); [SMSEagle webhook test](https://www.smseagle.eu/features/webhooks/); [tekservix battery settings](https://tekservix.com/blog/sms-gateway-app-battery-settings)).

Implementation phasing stays decision-ready. **Phase 0** freezes OpenAPI, status machine, capability schema, and policy hooks (message class, consent ref, quiet hours, caps, STOP list) with dry-run and audit log; ship a Rust client and generate TypeScript for web consumers. **Phase 1** ships desktop Makepad SMS-Gateway + Android companion over LAN HTTPS with mDNS/QR pairing, foreground-service health, explicit `subscriptionId` binding, and default-SMS role path planned for Play (or private/MDM distribution for owned shop devices) ([Android SmsManager](https://developer.android.com/reference/android/telephony/SmsManager); [Play default handlers](https://developer.android.com/guide/topics/permissions/default-handlers)). **Phase 2** adds USB modem backend with udev-stable names, ModemManager ignore rules, and allowlisted sticks; **Phase 3** adds appliance HTTP adapters and optional cloud-SMS backend behind the same outbox without hostageing local drain. Jurisdiction packs (`IN`/`EU`/`US`/`OTHER`) default India promotional sends off on unregistered handset mode and keep US/EU marketing behind express consent + STOP ([TRAI PDF](https://www.trai.gov.in/sites/default/files/2025-02/Regulation_12022025.pdf); [FCC DA-25-312](https://docs.fcc.gov/public/attachments/DA-25-312A1.pdf)). Success metrics are integrator-facing: one client works against phone or modem; pairing needs no typed IP; queue stalls surface as health failures within seconds; no Gotigin cloud required to send a consented transactional SMS on the shop’s own SIM.

## Conclusion
The market already proved that local SMS is a **spooler problem with messy radios**, not a missing Twilio clone: Android LAN HTTP and AT modem daemons work, but pairing, multi-backend contracts, offline client semantics, and shop-grade health UX remain fragmented, while compliance quietly forbids treating prepaid SIMs as stealth blast pipes. Wadhu’s structural advantage is the same independence model that already separates `escpos` crates from print apps — encode the brand-neutral outbox once, run SMS-Gateway as the appliance operators actually leave plugged in, and let every Gotigin and third-party app reuse the radio without inheriting OEM folklore or vendor cloud lock-in.
